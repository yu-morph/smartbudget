# 데이터 출처와 변환 규칙

## 원본과 결과

| 항목 | 내용 |
| --- | --- |
| 원본 | Kaggle [Personal Finance Data](https://www.kaggle.com/datasets/ramyapintchy/personal-finance-data) |
| 작성자 | Ramya Pintchy |
| 기록된 확인일 | 2026-09-18, 버전 1, MIT 표시 |
| 원본 파일 | `data/raw/Personal_Finance_Dataset.csv` |
| 변환 파일 | `data/processed/transactions.json` |
| 변환기 | `scripts/transform_data.py` |
| 선택 기간 | 원본 2020~2022년 |
| 결과 기간 | 2024-01-02~2026-12-31 |
| 거래 수 | 총 873건: 수입 238건, 지출 635건 |

원본 CSV는 보존하고 결과 JSON만 생성합니다. 원본의 2023년 이후 행은 사용하지 않습니다. 2024년 1월 1일에 맞추기 위해 거래를 새로 만들지는 않으므로 결과의 첫 날짜는 1월 2일입니다. 모든 날짜에 거래가 존재하는 것은 아닙니다.

데이터셋 라이선스 고지와 프로젝트 전체 라이선스의 구분은 [README](../README.md#데이터와-출처)에 기록되어 있습니다. 재배포 시 출처와 고지를 유지하고 원본의 최신 이용조건을 확인하세요.

## 변환 순서

1. 원본 CSV에서 `Date`가 2020~2022년인 행만 선택합니다.
2. 날짜의 연도에 정확히 4를 더합니다. 월·일은 유지합니다. 예: 2020-02-29 → 2024-02-29.
3. 선택된 행의 원본 순서대로 `txn-000001` 형식의 ID를 부여합니다.
4. 원본 카테고리를 아래 규칙으로 변환합니다.
5. 변환된 카테고리 기준으로 수입·지출 유형을 정합니다.
6. 금액을 카테고리별 원화 범위로 정규화합니다.
7. 설명을 카테고리별 한국어 목록에서 순환 선택하고 UTF-8 JSON으로 저장합니다.

무작위 난수를 쓰지 않습니다. 같은 원본과 같은 코드면 같은 결과가 나옵니다. 원본 행 순서를 바꾸면 ID와 순환 배분 결과가 달라질 수 있으므로 원본은 수정하지 않습니다.

## 카테고리 매핑

| 원본 카테고리 | 결과 |
| --- | --- |
| Food & Drink | `food` |
| Utilities, Rent | `housing_utilities` |
| Investment | `investment_income` |
| Entertainment | `leisure` |
| Health & Fitness | `health` |
| Salary | `salary` |
| Travel | `transport` |
| Shopping | 해당 카테고리 내 10행마다 shopping 7행, education 2행, other_expense 1행 |
| Other | 해당 카테고리 내 홀수 번째는 side_income, 짝수 번째는 other_income |

순번은 선택된 2020~2022년 행만 대상으로 세며 1부터 시작합니다. Shopping의 1~7번째는 `shopping`, 8~9번째는 `education`, 10번째는 `other_expense`로 반복합니다. 마지막 묶음이 10행 미만이면 전체 비율이 정확히 70/20/10이 되지는 않습니다.

`salary`, `side_income`, `investment_income`, `other_income`은 `INCOME`, 나머지는 `EXPENSE`입니다. 원본의 유형 값을 그대로 복사하지 않습니다. 따라서 원본에서 급여가 지출로 표시된 경우에도 변환 결과는 수입입니다. 이 매핑은 과제용 조회 테스트를 위한 것이며 실제 개인의 소비 분류를 복원하는 작업이 아닙니다.

## 금액 변환

환율을 적용하지 않습니다. 변환된 각 카테고리 안에서 원본 금액의 최솟값·최댓값을 구하고 다음 식으로 범위를 맞춥니다.

```text
비율 = (원본 금액 - 원본 최솟값) / (원본 최댓값 - 원본 최솟값)
변환 금액 = 목표 최솟값 + 비율 × (목표 최댓값 - 목표 최솟값)
최종 금액 = 변환 금액을 100원 단위로 반올림
```

원본 최솟값과 최댓값이 같으면 비율 0.5를 사용합니다. 결과는 양의 정수이고 수입·지출 부호는 금액이 아니라 `type`으로 구분합니다.

| --- | ---: | ---: | --- |

| transport | 1,500 | 1,000,000 | 서울교통, 한길택시, 스마트주유소 |

## 재생성과 검증

저장소 루트에서 실행합니다. 재생성은 기존 결과 JSON을 덮어씁니다.

```bash
.venv/bin/python scripts/transform_data.py
.venv/bin/pytest -v
git diff -- data/processed/transactions.json
```

원본과 변환기가 그대로라면 재생성 후 JSON 변경이 없어야 합니다. 변환 결과는 원본 순서로 저장되고 API 응답에서는 날짜·ID 내림차순으로 정렬됩니다.

원본 SHA-256:

```text
5e105d1b566e314c936cbc429b4c45e4b5fb8d94ff67f204cafb8b7f74ad8dd6
```

macOS에서는 `shasum -a 256 data/raw/Personal_Finance_Dataset.csv`로 확인할 수 있습니다.

자동 테스트는 변환 재현성, 873건, ID 중복 여부, 12개 카테고리, 날짜 +4년, 금액 범위·단위, 급여 수입 분류와 JSON 출력 형식을 확인합니다. API 테스트는 전체·날짜·기간·복합 필터, 대소문자 검색, 잘못된 입력, 빈 결과와 테스트 HTML 제공을 확인합니다.

JSON은 서버 시작 시 Pydantic 모델로 읽습니다. 파일 누락이나 잘못된 JSON·모델 값은 서버 시작을 실패시킵니다. 데이터의 모든 업무 규칙을 런타임 모델이 보장하는 것은 아니므로 데이터 변경 후에는 반드시 변환 테스트도 실행하세요.
